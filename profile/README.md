## EventSentry Highlights

- **Event Watch:** EventSentry event watch follows event records on computers you administer.
- **Log Alert:** EventSentry log alert tells you when a record matches a condition you care about, such as a failed sign-in or a stopped service.
- **Heartbeat:** EventSentry heartbeat shows that a watched computer is still reporting, so silence itself can be noticed.
- **Filter Rule:** EventSentry filter rule keeps ordinary noise out of the view so a small office is not buried in routine lines.
- **Status Page:** EventSentry status page gathers the current picture for a person who checks the systems in the morning.

## What Is EventSentry

EventSentry is an event-record helper for machines a small office or lab already runs. EventSentry event watch reads those records. EventSentry log alert raises the ones you decided matter. You are looking at your own computers, with permission to read their logs, not at systems outside your care.

EventSentry filter rule is what makes the watch usable. A busy host writes many lines that do not need a person. The filter keeps a failed sign-in, a stopped service, or another chosen condition visible. EventSentry heartbeat adds a different signal: the computer is still checking in. EventSentry status page puts the result where a morning review can see it.

The first setup should name a few conditions, not every possible line. EventSentry event watch, EventSentry filter rule, and EventSentry log alert work as a set. EventSentry heartbeat and EventSentry status page tell you the watch itself is alive. That is a practical loop for study labs and small offices that need a clear note, not a crowded console.

## Compatibility

| Component | Minimum | Recommended |
|-----------|---------|-------------|
| **Operating System** | Windows 10 | Windows 11 with the current EventSentry build |
| **Processor (CPU)** | Dual-core CPU | Modern multi-core CPU when several hosts report |
| **Memory (RAM)** | 4 GB | 8 GB or more while filters and the status page stay open |
| **Storage** | Space for the helper and recent records | Extra room for a longer event history |
| **Permissions** | Standard user access on the console | Admin rights to read event records on hosts you manage |

EventSentry event watch needs permission you already have on those computers. EventSentry filter rule should be tightened until EventSentry log alert is rare enough to trust.

## Starting with EventSentry

Prerequisites: A compatible computer, hosts you administer, and permission to run EventSentry and read their event records.

1. **Prepare:** Pick one server or lab PC whose records you are allowed to read.
2. **Start The Watch:** Turn on EventSentry event watch for that computer.
3. **Write One Filter:** Add an EventSentry filter rule for a failed sign-in or a stopped service.
4. **Raise The Note:** Connect that rule to EventSentry log alert.
5. **Check The Beat:** Confirm EventSentry heartbeat shows the computer is reporting.
6. **Open The Page:** Use EventSentry status page the next morning before you add more hosts.
